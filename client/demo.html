🔧 How It Works

Server Side:
1. Generate valid XHTML
2. Sign raw bytes (no parsing!)
3. Send with SHP-Signature header 
// Server code (Go)
xhtml := generateValidXHTML(title, content)
hash := sha256.Sum256([]byte(xhtml))
signature := rsa.SignPKCS1v15(privateKey, hash[:])

w.Header().Set("SHP-Signature", base64(signature))
w.Header().Set("Content-Type", "application/xhtml+xml")
w.Write([]byte(xhtml))
Service Worker:
1. Intercept response
2. Verify signature on raw bytes
3. Pass to browser if valid, block if invalid 
// Service Worker (JavaScript)
const htmlBytes = await response.arrayBuffer();
const valid = await crypto.subtle.verify(
    'RSASSA-PKCS1-v1_5',
    publicKey,
    signature,
    htmlBytes  // Raw bytes - no DOM!
);

if (valid) {
    return new Response(htmlBytes, {
        headers: {'Content-Type': 'application/xhtml+xml'}
    });
}
Browser:
1. Receive application/xhtml+xml
2. Strict XHTML parsing
3. Display verified content

🔐 Security Guarantees

✅ What's Protected:
  • Content integrity (cryptographic proof)
  • Structure validity (XHTML strict mode)
  • CDN injection attacks (any change = invalid signature)
  • Proxy modifications (bytes must match exactly)
⚠️ Attack Scenarios:

CDN Script Injection:
Original: <body><p>Content</p></body>
Injected: <body><p>Content</p><script>evil()</script></body>
Result: SHA-256 different → signature INVALID → BLOCKED

Broken HTML from Server:
Server signs broken HTML → Browser tries strict XHTML parsing → Error page → Admin fixes code
